# 陇上鲜集 / Longshang Fresh

从甘肃景泰起步的地方特产商城开源项目，逐步连接商品、产地内容、采购与订单服务。

**V0.8 增加云端库存与当前采收批次：采购者按规格设置可售份数、批次和日期；模拟订单原子扣减库存，取消同批次未发货订单只回补一次。商家账号权限、商品、素材、订单和售后继续云端同步。不接真实支付、快递或退款，尚未发布为微信小程序。**

2026-11-01 已发布 [托管版本9管理后台](https://jingtai-fresh-demo-1031.merry-brush-7565.chatgpt.site/admin?v=9)，179项测试及163项本机Worker接口检查通过。库存功能与验证边界见 [V0.8 验收记录](docs/QA-INVENTORY-2026-11-01.md)。历史记录保留在 [V0.7 商家账号记录](docs/QA-MERCHANTS-2026-11-01.md)、[V0.6 云订单记录](docs/QA-ORDERS-2026-11-01.md)和 [V0.5 商品素材记录](docs/QA-2026-11-01.md)。站点保持原私有访问范围，本轮不操作浏览器，真实手机交互尚未实测。

## 本机快速开始

需要 Node.js 22.13 或更新版本及其自带的 npm。运行静态演示无需安装云端框架依赖：

```sh
git clone https://github.com/yegeli/longshang-fresh.git
cd longshang-fresh
npm start
```

- 买家页面：[http://127.0.0.1:5173](http://127.0.0.1:5173)
- 管理后台：[http://127.0.0.1:5173/admin.html](http://127.0.0.1:5173/admin.html)，也支持 `/admin`。

该模式无需登录，只操作本浏览器演示数据。同一地址来源的买家和后台共享记录；`localhost`、`127.0.0.1`、不同端口与线上站点各自保存独立记录。源码在 `public/`，`dist/` 是云构建输出。

## 已实现的范围

- 买家五入口：逛好物、特产馆、看产地、购物车、我的；支持搜索、分类、收藏、足迹和商品详情。
- 六款模拟商品模板：苹果、枸杞、梨、土豆、玉米、洋葱；后台可新增商品、编辑两种规格与价格、保存草稿、上架和下架。
- 图片预设与文件上传、视频上传；保存并上架后，商品详情和对应产地内容读取同一素材绑定。
- 同一商家的多商品、多规格合并模拟订单，只计算一次演示运费；服务端重新报价并保存下单快照，改价或下架不改变旧单。跨商家商品暂需分开下单。
- 云端与本机后台支持订单备注、模拟发货和整单售后处理；买家可申请、撤回并查看处理意见和历史。内部备注只向有权限的后台显示。
- 云 API 支持平台登录状态、D1 角色与商品归属、版本冲突检查，以及 R2 素材上传和受控读取。普通登录账户无管理权，商家仅管理自己的商品与素材，管理员可管理全部商品。
- 云端后台新增“商家账号”：按登录邮箱录入采购者并在首次可信登录时绑定稳定身份，分别授予商品管理、订单发货、售后处理权限。支持地区筛选、启停、并发编辑冲突保护及操作记录；景泰／定边模板只填入模拟资料，不自动创建账号。
- 停用商家后禁止管理操作，隐藏其商品并拒绝新的购买请求；历史订单保留，由管理员处理。只有售后权限的采购者仅能看到自己的售后订单。账号资料与授权存在云端，本机静态模式不模拟真实授权。

云端后台新增“库存批次”：选择商品 → 设置库存 → 可点“填入模拟库存” → 核对两种规格、批次、日期和调整原因 → 保存。模拟按钮只填表，保存后才写入云端。**已有商品和新增商品默认未配置、可售数为0，需要设置后才能模拟下单**；不会自动填入虚构余量。旧订单保留且不会被迁移误扣库存。

买家可查看规格余量、采收批次和日期，订单保留下单时的批次快照。取消时只有整单各商品均为原批次且可安全回补才归还；任一换批次则整单标记待采购者核对，不自动加到新批次。售后处理不自动回库，升级前没有库存快照的订单也不回库。当前只管理每款商品的一个在售批次，不是完整多批次仓储系统。

本机后台首次打开会补充带标记的示例订单，保留已有有效订单。云端不自动导入本地记录或生成示例订单；管理员可显式初始化六款模拟商品，已有商品保持原样。云订单由已登录买家在商城实际点击“模拟下单”生成。

## 云端开发与部署

云端需要安装依赖、配置运行环境和数据库迁移。本地云预览使用独立模拟资源；托管环境使用 Worker、D1、R2 和 Sites 提供的 ChatGPT 身份入口。公开仓库不含现成站点的内部身份或凭据，也没有自建密码或 OAuth 系统。

```sh
npm install
npm run setup:local
npm run build
npm run db:local
npm run dev
```

构建后的本地 Worker 可使用 `npm run preview:cloud` 预览；具体地址以启动输出为准。本地身份模拟不是实际登录，不能公开暴露预览服务。设置、管理员初始化、权限和故障处理见 [云端运行说明](docs/CLOUD-OPERATIONS.md)，已验证与尚未覆盖的设备范围见 [验收记录](docs/QA-2026-11-01.md)。

## 演示边界

商品、产地、规格、价格、运费和业务记录均为模拟，不代表真实货源、库存或采购合作。下单不扣款，发货不生成真实运单，售后不实际退款或补发，客服为本地自动回复。

本机模式的商品、订单等记录保存在 localStorage，文件在 IndexedDB，没有服务端授权。云端模式的商品、订单、发货与售后保存到 D1，上传素材保存到 R2；**购物车、收藏、足迹与客服对话仍只在当前浏览器**。清理站点数据会丢失本地记录，不要在演示订单中使用真实客户资料。

上传成功不等于发布：素材通过商品保存并上架后的绑定才公开读取。来源与授权说明由上传者填写，不代表已审核版权或核实货源。云端连接、鉴权或保存失败明确报错，不会静默改存本机；只有静态服务器返回明确演示标记才启用本机模式。

手机可使用有站点访问权限的同一账户访问托管原型，文件选择、播放和布局尚未实机验证；登录也不会迁移本机订单。克隆本仓库可独立运行静态演示。

## 开发与参与

```sh
npm test       # 模型、存储、静态 HTTP 与云 API 测试
npm run check # JavaScript 语法检查及测试
```

测试覆盖模型、云 API、客户端存储及页面交互分支；云 API 测试使用 Node.js SQLite 执行实际生成的迁移，以适配器模拟 D1／R2。本轮的测试数量、构建、迁移和独立 HTTP 验证结果见 [库存批次验收记录](docs/QA-INVENTORY-2026-11-01.md)。这些结果不等于真实手机或登录页面的交互验收。

接入真实采购者时，需要录入其实际登录邮箱，并另行配置站点访问权限；创建商家档案不会自动邀请、注册登录账号或扩大站点访问范围。后续完善备份恢复、多批次仓储、跨商家拆单与运维；云端模拟订单不等于真实交易能力。支付接入与企业注册不是本轮原型开发前置步骤。
