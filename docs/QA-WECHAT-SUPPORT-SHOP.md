# 微信原生客服与店铺资料阶段验收

日期：2026-11-07。原生小程序新增咨询列表、咨询详情和店铺资料三个页面，合计21个页面、4个底部导航。继续使用模拟资料，不接支付。通过命令操作代码、微信开发者工具和GitHub，没有操作用户浏览器。

## 本次交付

- 买家可从商品、公开店铺及自己的订单发起文字咨询，在“我的 → 我的咨询”查看、搜索、筛选和继续咨询。客服回复、未读状态、结束及重新开启咨询保存到云端。
- 商家在“商家工作台 → 店铺客服”查看并回复本店咨询；管理员可处理全平台咨询。沿用原来的`aftersales`权限，显示名称改为“售后与客服”，没有扩展原商品或订单权限。咨询归属由服务器确定，买家不能传入其他买家或采购者编号。
- 商家在“商家工作台 → 店铺资料”修改本店名称、介绍、服务说明及展示图片。沿用`products`权限；采购者身份和地区仍由管理端授权资料确定。其他设备的旧版本保存会被拒绝，保留当前编辑内容。
- 店铺图片支持选择、上传、重试、更换和恢复示例图。上传完成后需要保存店铺资料才公开展示。使用既有云上传机制，图片仅支持JPEG、PNG和WebP，最大5MiB；商品与店铺素材目标不能混用，店铺不能绑定视频。
- 买家产区、采购者列表和店铺详情读取云端店铺资料与签名图片地址。没有在售商品的店铺不进入公开目录，管理预览不会绕过该条件。
- 客服采用进入页面及手动刷新获取更新，没有后台推送、自动回复或图片附件。待确认发送按账号、环境、咨询对象和买卖双方身份隔离保存原请求，重试使用原幂等编号，不把本机草稿伪装成云端成功。

## 权限与一致性

客服与店铺资料使用现有受控`meta`集合；没有新增集合、索引、客户端数据库权限、云套餐或共享存储规则。写操作在事务内重验账号及采购者状态，并与会话撤销、采购者停用等操作写入同一保护文档。

咨询最多200条消息、每条600字；当前演示服务的咨询索引最多200个会话，达到容量时明确报错，不静默删旧消息。列表当前一次返回授权范围内的完整索引，不宣称已支持无限历史分页。已读只推进到实际展示的消息位置，不会把随后到达的消息误标已读。旧请求即使遇到咨询关闭或商品下架，仍可确认其原来的幂等结果。

店铺资料只允许编辑自己的店铺，使用版本冲突校验；公开响应只包含展示资料，不包含身份、会话及内部管理字段。素材仍遵循[上一阶段的云媒体约束](QA-WECHAT-MEDIA.md)，用于公开展示，不用于机密附件；此阶段没有增加旧素材自动回收器。

## 真实云端与页面验证

通过已授权开发者工具CLI，仅增量部署本项目market函数。使用已验证管理员的真实微信账号，同时作为模拟买家和管理者，再独立登录一个客户端会话核对同步；没有把自动化夹具身份当成真实第二采购者。

真实云环境28项检查通过，覆盖：第二客户端身份、店铺资料同步与旧版本冲突、未绑定图片不可发现、图片保存公开及更换、旧公开图片入口失效、第二客户端读取新图片、原生图片解码、创建和发送幂等、双方未读、读取确认同步、旧状态版本冲突、关闭后禁止新消息但保留原请求回放、商品及自有订单咨询归属，以及第二客户端退出不影响原会话。

测试保留一份标为模拟的店铺资料、云端示例展示图及三条商品／店铺／订单咨询。原来的六款公开商品及库存保持不变，本阶段没有新增结算或扣减库存。云端图片更换后原生`wx.getImageInfo`成功读取1600×2400图片。

进一步通过原生咨询页面的发送方法提交商家回复：云端成功后输入清空、没有待确认请求；买家列表出现1条未读，进入会话看到四条实际消息，返回列表未读变为0。官方模拟器核对了买家咨询列表、双方消息与输入区、店铺资料及公开店铺展示；截图与运行记录保存在本机忽略目录。

## 手机操作路径与待补验范围

1. 扫描本次开发预览二维码，“我的”中微信登录。
2. 从商品或店铺点咨询，输入模拟问题并发送；在“我的咨询”查看记录。
3. 从“商家工作台 → 店铺客服”回复，买家重新进入咨询或点击刷新查看。结束咨询后可重新开启。
4. 在“商家工作台 → 店铺资料”修改介绍、上传图片并保存，再进入买家店铺核对。上传完成但未保存的图片不会立即替换公开店铺。

当前真实云端同步由同一真实微信身份的两个独立客户端会话验证。两个不同采购者账号、两台真实手机，以及手机键盘与系统相册选图尚待实际设备补验；权限隔离自动化测试不能替代这些人工验收。没有提交微信审核或正式发布。

代码通过命令推送并核对远端提交及GitHub Actions，具体提交链接在交付消息中提供。GitHub只备份可公开源码和文档，不会自动备份云数据库及用户上传的媒体。
