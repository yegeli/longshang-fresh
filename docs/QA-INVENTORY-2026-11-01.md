# V0.8 云端库存与采收批次验收

日期：2026-11-01（Asia/Shanghai）。本轮继续使用模拟资料，不接支付、真实物流或退款；全程通过命令行和 API 实施，不操作用户浏览器。

## 已实现

- 后台“库存批次”按商品独立管理两种规格的可售份数、当前批次、采收日期和说明。只有商品管理权限的采购者能管理自己的库存，管理员可管理全部。可筛选未配置、缺货、低库存并查看最新50条记录。
- 模拟按钮只填表，保存才写云端；已有和新增商品均不自动填入正库存，未配置为0，不能新下单。人工库存是当前可售余量，不是总产量或初始入库量。
- 买家商品与结算页显示库存和当前批次，缺货禁止选购，库存读取失败不沿用旧的可售提示。下单保存批次快照，批次变动需重新确认。
- 服务端重新校验商品与库存版本，下单、扣减和记录在同一 D1 事务内完成；相同幂等请求不重复扣减。兼容升级前已经成功的旧请求重试，不允许旧格式创建新订单。
- 取消未发货订单时，整单所有商品仍为原批次且数量可安全回补，才回补一次；任一换批次则整单标记待人工核对，库存不自动增加。售后不自动回库，旧无库存快照的订单也不回库。
- 追加 `product_inventory`、`inventory_events`，不修改已应用迁移，不删除原有用户、商品、订单或素材。

## 边界与使用方法

1. 管理员或有商品权限的采购者进入“库存批次”，选择商品并设置库存。
2. 可点“填入模拟库存”，核对两种规格可售份数、批次、日期与调整原因，再保存。
3. 买家刷新商品后选购，成功模拟下单会扣库存；取消符合条件的订单可观察回补，改批次后取消可观察待核对。

本轮只管理每款商品一个当前采收批次，不是完整多仓、多批次库存或实际盘点系统。仍需独立D1／R2备份恢复与真实供货验收。退款、补发只是模拟处理意见，不自动调整实际库存。

站点保持原私有访问范围，真实采购者需另外获得站点访问权限。没有真实手机／桌面浏览器视觉、登录跳转或多设备人工点击验收。源码推送不等于运行时数据库和媒体备份。
