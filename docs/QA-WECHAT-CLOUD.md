# 微信云开发与运营端验收

本阶段增加CloudBase适配及原生运营端，保留旧HTTP和Sites实现。以下区分代码验证与真实云结果；默认原生源码仍是本机模拟，不能据此声称已完成手机与历史网页后台的同步。

## 已实现

- 原生页扩至16个：买家13页，另加商家工作台、商品资料／价格／库存、微信采购者账号管理。
- 微信采购者按服务端验证的账户编号绑定，商品、订单、售后三项权限分开；无权限用户不因点击入口取得权限。
- HTTP后端首管受控CLI及微信采购者API，原Sites邮箱绑定路径保持兼容。
- CloudBase可信上下文身份、每设备会话、精确环境配置、登录退出、云商品和购物资料、库存、幂等订单、模拟发货／收货／售后。
- 数据按独立文档存储，采用官方SDK真实事务。测试夹具遵循快照隔离；业务写入与撤权、退出、停卖、改价写入共同保护，避免仅读授权文档造成写入竞争。
- 仅面向13个 `lsf_` 集合的受控初始化函数；默认只读，显式操作者才可分步创建、核验ADMINONLY及索引定义，最后发布应用／环境／清单匹配的就绪标记。
- 生成独立云开发部署包，原mock工程和旧数据保持独立；真实配置、二维码和运行状态不进入GitHub。

## 真实部署与剩余验证

准备阶段已生成独立CloudBase项目。受控初始化函数已通过官方微信CLI上传成功，使用本机锁定并验证的依赖（约14.8MB），没有开启远端npm安装。官方函数信息已核实运行时为Nodejs16.13、默认3秒；首次创建时遇到Creating状态，读取Active后正常续传成功。

初始化函数当前没有配置操作者，只允许可信微信身份查询；还未创建、修改或写入商城业务集合。真实执行角色权限、集合访问规则与就绪标记尚未实测，不能写成真实云同步完成。官方运行时命令接口的首次用户连接授权仍待确认。初始化缺少权限时停止；不会自动开收费套餐、扩大云角色授权、关闭客户端规则或改用本机保存。

接下来顺序：核对并部署新函数 → 可信微信操作者身份 → 分步核验集合规则 → 精确首管绑定 → 原生云预览 → 手机与电脑端完整业务联调。所有模拟资料仍不接支付、真实物流或退款。
