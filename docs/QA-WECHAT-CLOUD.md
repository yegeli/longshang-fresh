# 微信云开发与运营端验收

本阶段增加CloudBase适配及原生运营端，保留旧HTTP和Sites实现。以下区分代码验证与真实云结果；默认原生源码仍是本机模拟，不能据此声称已完成手机与历史网页后台的同步。

## 已实现

- 原生页扩至16个：买家13页，另加商家工作台、商品资料／价格／库存、微信采购者账号管理。
- 微信采购者按服务端验证的账户编号绑定，商品、订单、售后三项权限分开；无权限用户不因点击入口取得权限。
- HTTP后端首管受控CLI及微信采购者API，原Sites邮箱绑定路径保持兼容。
- CloudBase可信上下文身份、每设备会话、精确环境配置、登录退出、云商品和购物资料、库存、幂等订单、模拟发货／收货／售后。
- 数据按独立文档存储，采用官方SDK真实事务。测试夹具遵循快照隔离；业务写入与撤权、退出、停卖、改价写入共同保护，避免仅读授权文档造成写入竞争。
- 仅面向13个 `lsf_` 集合的受控初始化函数；默认只读，显式操作者才可分步创建、核验ADMINONLY及索引定义，最后发布应用／环境／清单匹配的就绪标记。
- 生成独立云开发部署包，原mock工程和旧数据保持独立；真实配置、二维码和运行状态不进入GitHub。

## 真实部署与剩余验证

2026-11-07 已完成实际CloudBase部署和完整模拟交易联调。两个函数通过官方CLI上传锁定依赖，分别约14.7MB、6.7MB，不使用远端npm安装。真实调用发现并修复了SDK漏声明mime-db、平台附加字段被误拒绝、checkpoint误写数据库_id、默认内建索引结构差异。早先本机SDK导入检查会借用仓库根依赖，现已改为真正隔离两个部署包并加载实际入口。

官方微信CLI连接授权已生效。初始化操作者来自实际wx.cloud.callFunction的可信微信上下文；服务端精确配置该账户，首管通过单例事务绑定。商城函数30秒已通过受控接口设置并读回Active；初始化函数自身的3秒限制会中断配置请求，最终只在微信开发者工具原生云控制台改为15秒，界面和CLI均已读回确认。没有操作Chrome或其他用户浏览器，没有扩大云执行角色、购买套餐或修改四个旧云函数。

13个商城集合已按固定清单建立，创建时ADMINONLY，之后分步核对ACL、微信安全规则和索引定义。恢复已有checkpoint后完成最终复核，2026-11-07 16:12（Asia/Shanghai）写入应用、环境及清单匹配的就绪标记。没有绕过就绪门禁或重建清空数据。

使用同一真实微信账户的两个独立会话完成以下云端操作：登录为管理员、仅初始化缺失的六款商品、生成模拟订单、相同提交重复请求返回同一订单、只扣一次库存、另一会话读取订单、模拟发货、确认收货、申请售后、处理售后并读回结果。订单最终版本为5，收货状态received、售后resolved；售后没有补库存。六款商品首次20／12份，测试后苹果小份19，其余仍20／12。没有付款、真实运单或真实退款；测试会话已退出。

官方CLI已生成新CloudBase开发预览，包体1,366,601字节。新版模拟器首页实际读取6款商品，mode为cloud、无页面错误或图片加载错误，截图已检查；体验指南补充了原生商家发货和售后的具体入口。用户用管理员微信在真实手机扫码并登录后，已确认能看到商品和商家工作台。手机手动下单至售后的逐步操作、另一名实际采购者的账号隔离仍待后续验收；上述完整业务链路是开发者工具调用真实云函数的结果，不能替代这些人工验收。小程序尚未提交审核或正式发布。
