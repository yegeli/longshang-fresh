# 微信原生工程阶段验收

本轮交付的是原生小程序源码、完整模拟业务和微信登录服务端实现。尚未取得本机已登录后台的实际AppID，未上传微信预览、未完成手机扫码、未提交审核或正式发布。历史 `chatgpt.site` 手机网页不计作微信小程序交付。

## 已实现

- 13个原生页面、4个底部导航：首页、产区与详情、店铺列表与详情、商品详情、购物车、结算、订单列表与详情、售后、我的、完整指南。使用WXML／WXSS／Page／App，没有web-view壳。
- 六款模拟商品、本机首次20／12份库存；同店结算、价格与库存快照、幂等下单、取消批次检查、模拟发货、收货、售后及结果回看。刷新不重置库存。
- 本机模拟和云模式明确区分；云模式通过 `wx.login` 接口取得项目会话，不携带Sites服务密钥，不上传本机旧数据。云失败不切回本机。
- 微信 code 交换、不透明会话、哈希持久化、到期与退出撤销、重复 code 保护、独立微信身份和公开Worker入口。采购者或管理员不通过客户端字段、相同邮箱、首个访客自动授予。
- 购物车版本冲突、账号切换、旧读取、下单响应丢失、存储失败与订单成功后的清理失败处理。只有本机模拟模式显示“模拟商家发货／处理售后”按钮。
- 项目AppID配置、源码包体检查、官方离线编译、受控命令行预览脚本及GitHub阶段备份流程。

实际Worker测试发现并修正了 `redirect:'error'` 在Cloudflare运行时不可用的问题；提供方请求现为 `manual` 且拒绝非2xx，避免带密钥跟随重定向。运行兼容层只补缺失的 `Object.fromEntries`、`Object.hasOwn`、`Array.flatMap`，并在缺失这些方法的VM中测试。

官方原生编译器固定版本仅提供macOS／Windows二进制，Ubuntu CI负责源码、包体、业务与Worker HTTP检查，不冒充官方编译或实机验收。独立官方工具依赖锁定在 `tools/wechat/package-lock.json`。

## 外部步骤与验证边界

用户已说明有微信小程序账号，并授权只读查看后台AppID；尝试查看时Mac锁屏，未读取成功，也没有改微信后台设置。需要解锁后继续读取实际AppID并配置本机工程。

命令行生成微信预览还需用户准备授权上传私钥，或通过已登录的微信开发者工具预览。本机未安装微信开发者工具，本轮安装的是隔离的官方npm编译工具。上传脚本目前仅验证本机输入和保护逻辑，未使用真实上传私钥执行，因此没有预览二维码可交付。

真实云同步还需独立API部署授权、服务器AppSecret、D1／R2绑定和微信合法域名。本机Cloudflare CLI检查返回未登录；不替用户创建付费资源，不把Sites私有资源标识或访问令牌用于小程序。独立新库的管理员／采购者绑定与旧数据迁移仍需受控实现；当前微信新账号仅为买家。

没有真实微信登录、上传预览、手机触控／视频播放、跨设备小程序同步或审核发布结果。现有网页云库存和演示站点没有被本轮测试修改。继续使用模拟资料，不接支付、真实物流或退款。
