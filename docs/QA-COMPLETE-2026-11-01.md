# V1.0 完整模拟业务版验收

日期：2026-11-01。范围为可完整体验的模拟商城，不接支付、真实运单、退款或外部客服；保留原站点访问范围。全程未操作浏览器或Computer Use。

## 完整业务路径

| 环节 | 本轮结果 |
| --- | --- |
| 商品准备 | 管理员商家权限、采购者登录绑定、商品编辑上架、图片视频绑定及库存沿用现有云服务；后台首页增加完整流程入口 |
| 买家浏览 | 首页、产区、采购者店铺和商品详情连通，搜索／分类／有货筛选及采收素材入口保留 |
| 账号购物资料 | 购物车、收藏、足迹、示例地区偏好保存D1，同账号可跨请求／设备读取；匿名浏览不落本机假云记录 |
| 模拟下单 | 按店结算、服务端报价、库存扣减与原请求重试保护保留 |
| 清理购物车 | 根据成功订单快照扣减当前选中数量，保留未选和额外数量；持久幂等与事务保护，失败不误报下单失败 |
| 发货与收货 | 商家记录演示物流，订单买家确认模拟收货，双方看到已完成；重复、越权、旧版本及状态不允许时拒绝 |
| 售后 | 确认收货后仍能从订单申请售后，后台处理并填写意见，买家读取结果，无真实退款或补发 |
| 使用引导 | 买家帮助页完整体验指南、使用设置，后台商品／库存／订单／售后操作入口 |

## 审查中修复的边界

- 修正筛选函数新增参数后被Array.filter索引误用而导致订单列表为空，并加入订单卡真实渲染回归。
- FAQ改用稳定主题ID，增加使用指南不再让运费／售后等自动回复错位。
- 订单成功后库存刷新、清车等待期间再次检查账号；旧账号订单不会进入新账号的购物车清理提醒或导航。
- 忙碌页面延迟重绘时记录待刷新状态，恢复空闲后即使云数据未再次变化也会更新。
- 订单成功后先登记按账号的清车恢复标记，再清除下单pending并等待库存；标记无法持久时保留原pending，清车确认后只清除匹配原请求的记录，避免刷新页面丢失恢复入口。
- 云购物车保留不可见商品占位，不在修改另一款商品时悄悄移除旧行。
- 云写按账号串行，冲突或网络结果不确定只重新GET核对，不自动重放写；晚到读取不能覆盖新保存，旧账号响应不能应用到新账号。

## 尚未作为真实业务验收的范围

- 没有真实手机／桌面浏览器渲染、触控、文件选择、播放或多账户人工登录验收；Node轻DOM及HTTP检查不能证明真机交互已通过。
- 仍是托管网页商城原型，未发布到微信小程序平台；支付、经营收款、真实货源与物流合作不在模拟业务范围。
- 当前店铺介绍与商品数据为模拟，采收视频只有后台真实绑定素材后才能播放；不把示意图片当实拍或品质凭证。
- 生产库存不自动添加，首次体验新下单前需由有权限的操作者显式核对保存模拟库存。
- 客服是本地自动回复，售后凭证仍为示意图片，不包含人工客服、真实退货、部分商品退款或采购结算。
- 原私有站点的访问授权继续独立管理，商家档案不会自动授予站点访问权。本机旧购物资料不会自动上传。
