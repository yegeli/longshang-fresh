# V0.7 商家账号与权限验收

日期：2026-11-01（Asia/Shanghai）。使用模拟资料，不接支付；全程通过命令行与 API 开发、验证、发布和备份，未操作用户浏览器。

## 本轮实现

- 管理员后台增加“商家账号”：创建、地区与状态筛选、修改、三项权限分配、停用／启用和操作记录。支持景泰与定边模拟模板，模板只填表，保存才写入云端。
- 按采购者实际登录邮箱登记业务档案；首次经过可信入口登录时绑定稳定身份，绑定后不允许换邮箱转移账号。相同邮箱的另一身份不能继承账号，明确撤销的角色不会重复自动恢复。
- 商品管理、订单发货、售后处理独立授权，服务端按归属和当前权限校验；只授予售后权限时只能读取自己已经发生售后的订单。商家不能管理账号或其他商家的资料，管理员保留全部管理权。
- 停用后禁止后台操作，隐藏该商家的商品及其仅由这些商品公开的素材，拒绝新报价和新订单。已存在的订单、售后及幂等重试结果保留，管理员可继续处理。
- 每次档案变更使用版本检查，审计与写入同事务；冲突不覆盖草稿、不产生错误审计。权限或身份变化时清空旧页面状态，阻止过期异步响应恢复数据。
- 追加 `merchant_accounts`、`merchant_audit` 迁移，保留既有用户、商品、素材和订单；不自动向生产库注入模拟商家或订单。

## 验证边界

- 未进行真实手机、浏览器视觉布局、真实登录跳转或多设备人工点击验收；不把 HTTP／控制器测试称为实机测试。
- 登录沿用 Sites 的可信 ChatGPT 身份。商家档案不是新建 ChatGPT 登录账号，不设置密码、不发送邀请邮件。实际采购者仍需单独获得站点访问权限，站点继续保持原私有受众。
- 模拟模板邮箱不能登录；使用真实采购者前应在尚未绑定时更换为实际登录邮箱。本轮没有添加真实商家、客户或支付资料。
- 同一账号通过云端读取相同业务记录；页面刷新或可见时定期重新读取权限，并非实时推送。已发出的服务端写入仍执行当前权限检查。
- GitHub 备份包含源码、迁移、测试和文档，不包含云端业务数据或密钥。真实运营前仍需独立的 D1／R2 备份恢复方案。
