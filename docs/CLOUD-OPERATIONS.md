# 云端运行与维护

V0.6 将商品目录、商家权限、素材、模拟订单、发货和售后接到云端。购物车、收藏、足迹与客服仍是本浏览器记录；没有真实支付、物流或退款接口。下面区分已编写的功能和仍需实际环境验证的事项，不把本地测试当作线上验收。

## 两种运行模式

| 模式 | 启动与数据 | 适用范围 |
| --- | --- | --- |
| 本机演示 | `npm start` 提供 `public/`；商品等记录在 localStorage，文件在 IndexedDB | 克隆后体验页面与本机业务；没有登录、服务器授权或跨设备同步 |
| Sites 云端 | Worker 处理 `/api/v1/*`；D1 保存身份角色、商品、订单售后和素材元数据，R2 保存上传文件 | 通过 Sites 身份管理云商品及授权订单；买家登录后读取自己的订单 |

静态服务器的 `/api/v1/session` 使用明确的 `404` 加 `{"mode":"local-demo"}` 标记。只有这个响应允许前端启用本机演示。网络异常、未标记的 404、鉴权错误或 5xx 不会静默切回本机保存。云端新建目录初始可以为空，不能以默认六款商品掩盖读取失败。

普通静态托管若没有该标记接口，不能直接当作云端部署。自行托管云 API 还需实现可靠的身份网关和存储绑定；仅把文件放到公共 HTTP 服务器不等于拥有安全的后台。

## 本地云预览

使用 Node.js 22.13 或更新版本，在项目根目录运行：

```sh
npm install
npm run setup:local
npm run build
npm run db:local
npm run dev
```

`setup:local` 从 `hosting.example.json` 创建忽略的 `.openai/hosting.json`，并在不存在时创建忽略的 `.dev.vars`，不会覆盖已有配置。示例绑定为 `DB`／`BUCKET`，不包含托管站点 ID。默认初始化邮箱 `seedy@sites.test` 仅配合本地回环开发插件的 `local_seedy` 模拟身份；不要把它当作真实账户或复制为生产管理员配置。

开发插件在本机登录入口模拟登录和退出，先删除传入身份头，再仅对回环来源注入模拟身份。这里无需填写真实邮箱或密码，也不证明平台真实登录已通过。不要将开发预览暴露到公网。

`npm run db:local` 使用构建输出配置，将实际迁移应用到 `.wrangler/state` 的本地库；不修改托管数据库。schema 变化后运行 `npm run db:generate`，检查生成的 SQL，再重新构建和应用未执行迁移。不要删除本地库来掩盖迁移错误。

`npm run preview:cloud` 启动构建后的本地 Worker，地址以命令输出为准。它没有 Vite 的浏览器模拟登录中间件；不能把这个入口的匿名结果当成托管登录失效，也不能据伪造头测试宣称已验证真实身份。托管发布需配置自己的站点、资源和运行时值，保留 Sites dispatch 登录集成。

## 身份与管理员初始化

Sites dispatch 管理 ChatGPT 登录并提供受信任的 `oai-authenticated-user-id`、`oai-authenticated-user-email`。本项目使用站点内稳定用户 ID 关联权限和商品归属，邮箱用于初始化匹配和显示。登录通过顶层链接进入 `/signin-with-chatgpt`；项目不自建 OAuth、密码或另一套会话服务。

`BOOTSTRAP_ADMIN_EMAIL` 是部署环境配置项，不写进源码或浏览器脚本。首次以匹配的受信任平台身份访问时，D1 的 `admin_bootstrap` 单例记录绑定该稳定用户 ID，并授予一次管理员权限。后续同邮箱不同 ID 不会重新取得管理员；已绑定账户被降级后也不会因再次登录自动恢复。

设置步骤：

1. 使用部署平台的运行时配置设置 `BOOTSTRAP_ADMIN_EMAIL`，通过平台确认目标账户身份；不要把真实值提交 Git。
2. 部署迁移后，以目标账户登录 `/admin.html`，核对会话显示的权限。
3. 确认 D1 单例已绑定预期的稳定 ID；完成后可移除初始化邮箱配置。
4. 新商家先登录一次生成 `users` 记录，再由数据库维护者按稳定 ID 授予 `merchant`。当前没有网页角色管理或自助招商功能。变更前核对账户，并保存维护记录。

| 角色 | 云端权限 |
| --- | --- |
| 匿名 | 读取已发布商品与素材，不能查看订单或管理 |
| buyer（已登录） | 按服务端报价模拟下单、查看和取消自己的订单、申请或撤回售后；不能管理发货 |
| merchant | 管理自己创建的商品和自己作为卖家的订单；上传与绑定自己的素材，读取自己的未发布素材 |
| admin | 管理全部商品、素材和订单，显式初始化六款模拟商品；可绑定不同归属的素材 |

这里的“公开读取”指应用 API 的已发布可见性，站点整体仍受 Sites 的访问策略限制；私有站点不会因此变成公开站点。

所有管理请求由服务器重新查询 D1 角色，不能凭前端按钮、请求正文中的角色或邮箱获得权限。写接口要求同源 `Origin`。Sites 的服务访问凭据只解决站点访问边界，不代表某个商家身份，也不授予这些管理权限。

**自行托管的身份边界：** 本 API 信任上述身份头的前提，是入口由可信 dispatch 过滤并注入这些头。不得把接受任意客户端同名请求头的裸服务公开部署；自行托管者需替换身份适配器或部署能验证身份、删除伪造头且封闭源站的网关。开发测试中伪造请求头仅用于模拟这个受信边界。

## 数据、迁移与素材

运行时绑定名为 `DB`（D1）和 `BUCKET`（R2）。托管配置与身份保存在忽略的 `.openai/` 中，公开仓库不包含某个现成站点的内部身份、凭据或运行数据。使用者需为自己的环境配置独立资源。

`db/schema.ts` 定义 `users`、`admin_bootstrap`、`products`、`media` 和 `orders`。SQL 迁移由 schema 生成并纳入源码；请求处理不会临时建表。已应用迁移不可改写，后续变更追加迁移。本地模拟库与托管 D1 是两个环境，不能认为本机初始化会自动出现在云端。

管理员可显式初始化六款模拟商品；初始化只插入缺失的编号，保留已有商品。商品最多 200 款，当前每款两种规格、整数分价格。保存携带 `expectedVersion`，版本不符返回 409；前端保留表单，须明确放弃修改并重新读取后再编辑。

上传支持 JPG、PNG、WebP、GIF（最大 5 MiB）及 MP4、WebM（最大 30 MiB），需要素材来源与授权说明。浏览器先检查可读取性，服务器再检查实际接收大小、声明格式与文件签名；这不是完整媒体解码、转码、恶意文件扫描或版权审核。编码兼容性仍需目标浏览器实际播放验证。

R2 写入成功且 D1 元数据保存成功后才确认上传成功。若 D1 失败会尝试清除对象，不报告保存成功。选择文件会先上传，但只有保存商品并上架后才向买家发布绑定；离开未保存表单或替换文件可能留下私人、未引用素材。当前没有素材库清理界面或定时回收任务，应按 D1 引用关系核对后再人工清理，不能按文件创建时间直接删除。

素材读取统一经 `/api/v1/media/:id` 校验：未发布、未被在售商品引用的素材仅归属商家或管理员可读。商品下架或撤换后，原素材若无其他在售引用即恢复受限；此前已下载的副本无法撤回。接口支持 HEAD、单段 Range 与 416 响应，用于浏览器视频拖动，不直接公开整个 R2 桶。

素材来源文字由上传者填写，不构成已获授权的证明。内置图片仍按 [第三方素材说明](../THIRD_PARTY_NOTICES.md) 单独许可；历史 Pexels 视频与封面不随仓库提供。

## API 与故障处理

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/session` | 当前身份、角色、登录与退出入口 |
| `GET /api/v1/products` | 已发布目录 |
| `GET /api/v1/admin/products` | 当前商家可管理的目录，管理员可读全部 |
| `PUT /api/v1/admin/products/:id` | 按归属和预期版本新建或更新商品 |
| `POST /api/v1/admin/seed` | 管理员初始化模拟商品，JSON 正文为 `{}` |
| `POST /api/v1/media?kind=image\|video` | 上传二进制文件，携带文件名与来源请求头 |
| `GET\|HEAD /api/v1/media/:id` | 按发布状态或身份读取素材 |

订单接口与字段见 [API说明](API.md)。`GET /orders`按买家身份、`GET /admin/orders`按管理范围返回记录。创建必须携带服务端报价版本与幂等键；发货、备注、售后和取消必须带expectedVersion。客户端金额只用于确认一致性，保存金额由服务端计算。不能提交任意订单JSON、买家或卖家身份。

遇到保存、上传或同步失败时，先保留表单并核对页面错误；不要把本机记录或上一次目录当成已写入云端。401/403 需重新确认登录与角色，409 需处理编辑冲突，413/415 需更换文件，503 需检查绑定、迁移和运行资源。错误响应不会返回底层数据库异常或凭据。

## 发布与验收

发布前执行 `npm run check`，并按当前部署配置完成 schema 迁移与 Worker 构建。以下必须在实际受信入口补验，单元测试不能代替：

- 匿名和无管理权限账户不能直接读写管理接口，商家不能改其他商家的商品或引用其私有素材。
- 第一次初始化绑定正确；其他稳定 ID 即使邮箱相同也不能再次初始化管理员。
- 上传、保存、刷新、跨设备查看和视频拖动通过；未保存素材不能公开读取，下架后原素材失去公开可见性。
- 并发版本冲突、断网、存储失败和权限撤销均显示失败，保留编辑内容，且不切换到本机后台。
- 云端订单按账户同步；本机旧订单不上传。两种模式均为模拟，不扣款、不实际发货。

当前源码实现和自动化检查结果需与发布记录一起核对。本次已完成的托管和真实文件验收见 [2026-11-01 验收记录](QA-2026-11-01.md)；以下检查表仍用于后续发布，不能据一次通过推定所有账户、设备或故障情形均已实际覆盖。

本次独立源码检查已执行九组仓库云 API 测试，基于实际 SQL 迁移覆盖权限、初始化、版本、上传和媒体可见性。额外临时检查验证了商家角色撤销即时生效、多个在售引用撤下后的素材权限、私有 HEAD 在访问 R2 前拒绝，以及长度谎报与底层异常不泄漏。额外脚本为本地 QA，不替代真实 D1／R2 和平台入口验收。

备份恢复、审计日志、商家角色管理、上传配额、素材回收、完整媒体转码和旧本机订单迁移仍是后续工作。维护者应在接入真实数据前完成 D1 数据及 R2 对象的配套备份、恢复演练和角色恢复流程；本仓库目前没有自动备份任务。

R2 Range 与对象读取实现参考 [Cloudflare R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。Sites 身份与资源绑定以安装版本的 Identity and Secrets、Storage 说明为准。
