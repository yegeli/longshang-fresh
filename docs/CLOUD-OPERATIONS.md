# 云端运行与维护

V0.8在云商品、素材、商家权限、模拟订单与售后基础上，增加每规格可售库存、当前采收批次、下单原子扣减、取消回补与库存记录。购物车、收藏、足迹与客服仍是本浏览器记录；没有真实支付、物流或退款接口。下面区分已编写的功能和仍需实际环境验证的事项，不把本地测试当作线上验收。

## 两种运行模式

| 模式 | 启动与数据 | 适用范围 |
| --- | --- | --- |
| 本机演示 | `npm start` 提供 `public/`；商品等记录在 localStorage，文件在 IndexedDB | 克隆后体验页面与本机业务；没有登录、服务器授权或跨设备同步 |
| Sites 云端 | Worker 处理 `/api/v1/*`；D1 保存身份角色、商品、库存批次与记录、订单售后和素材元数据，R2 保存上传文件 | 通过 Sites 身份管理云商品及授权订单；买家登录后读取自己的订单 |

静态服务器的 `/api/v1/session` 使用明确的 `404` 加 `{"mode":"local-demo"}` 标记。只有这个响应允许前端启用本机演示。网络异常、未标记的 404、鉴权错误或 5xx 不会静默切回本机保存。云端新建目录初始可以为空，不能以默认六款商品掩盖读取失败。

普通静态托管若没有该标记接口，不能直接当作云端部署。自行托管云 API 还需实现可靠的身份网关和存储绑定；仅把文件放到公共 HTTP 服务器不等于拥有安全的后台。

## 本地云预览

使用 Node.js 22.13 或更新版本，在项目根目录运行：

```sh
npm install
npm run setup:local
npm run build
npm run db:local
npm run dev
```

`setup:local` 从 `hosting.example.json` 创建忽略的 `.openai/hosting.json`，并在不存在时创建忽略的 `.dev.vars`，不会覆盖已有配置。示例绑定为 `DB`／`BUCKET`，不包含托管站点 ID。默认初始化邮箱 `seedy@sites.test` 仅配合本地回环开发插件的 `local_seedy` 模拟身份；不要把它当作真实账户或复制为生产管理员配置。

开发插件在本机登录入口模拟登录和退出，先删除传入身份头，再仅对回环来源注入模拟身份。这里无需填写真实邮箱或密码，也不证明平台真实登录已通过。不要将开发预览暴露到公网。

`npm run db:local` 使用构建输出配置，将实际迁移应用到 `.wrangler/state` 的本地库；不修改托管数据库。schema 变化后运行 `npm run db:generate`，检查生成的 SQL，再重新构建和应用未执行迁移。不要删除本地库来掩盖迁移错误。

`npm run preview:cloud` 启动构建后的本地 Worker，地址以命令输出为准。它没有 Vite 的浏览器模拟登录中间件；不能把这个入口的匿名结果当成托管登录失效，也不能据伪造头测试宣称已验证真实身份。托管发布需配置自己的站点、资源和运行时值，保留 Sites dispatch 登录集成。

## 身份与管理员初始化

Sites dispatch 管理 ChatGPT 登录并提供受信任的 `oai-authenticated-user-id`、`oai-authenticated-user-email`。本项目使用站点内稳定用户 ID 关联权限和商品归属，邮箱用于初始化匹配和显示。登录通过顶层链接进入 `/signin-with-chatgpt`；项目不自建 OAuth、密码或另一套会话服务。

`BOOTSTRAP_ADMIN_EMAIL` 是部署环境配置项，不写进源码或浏览器脚本。首次以匹配的受信任平台身份访问时，D1 的 `admin_bootstrap` 单例记录绑定该稳定用户 ID，并授予一次管理员权限。后续同邮箱不同 ID 不会重新取得管理员；已绑定账户被降级后也不会因再次登录自动恢复。

设置步骤：

1. 使用部署平台的运行时配置设置 `BOOTSTRAP_ADMIN_EMAIL`，通过平台确认目标账户身份；不要把真实值提交 Git。
2. 部署迁移后，以目标账户登录 `/admin.html`，核对会话显示的权限。
3. 确认 D1 单例已绑定预期的稳定 ID；完成后可移除初始化邮箱配置。
4. 在后台“商家账号”按采购者的可信登录邮箱创建档案，填写名字、地区、启用状态和权限。首轮使用 `example.test` 模拟邮箱，不发送邮件。采购者后续首次可信登录时自动绑定稳定 ID；无需手工 SQL 赋角色，角色本身也不足以获得权限。

| 角色 | 云端权限 |
| --- | --- |
| 匿名 | 读取已发布商品与素材，不能查看订单或管理 |
| buyer（已登录） | 按服务端报价模拟下单、查看和取消自己的订单、申请或撤回售后；不能管理发货 |
| merchant | 需已绑定且启用的档案；products管理自己商品、素材、库存与当前批次，orders读取自己订单并发货／备注，aftersales读取及处理自己已有售后订单 |
| admin | 三权限全部具备；管理全部商品、素材和订单，显式初始化六款模拟商品；管理商家档案、权限和审计 |

这里的“公开读取”指应用 API 的已发布可见性，站点整体仍受 Sites 的访问策略限制；私有站点不会因此变成公开站点。

商家档案最多200份。邮箱去空格并转小写且唯一；未绑定时可改，绑定后不可改。可信身份以后换邮箱仍沿用原稳定 ID；同邮箱的另一个 ID 不会继承档案，同一 ID 也不能绑定第二份档案。即使档案已停用，首次匹配仍完成绑定，但不给操作权；明确撤销角色后不因重复登录恢复。不能通过此后台创建管理员，已知管理员邮箱和账号受到保护。

`products`、`orders`、`aftersales` 可独立授予或撤回，空权限不进入管理业务。仅售后权限者只能读取自己已有售后的订单，不能查看其余订单、发货或保存内部备注。地区用于标识采购来源，不允许同地区采购者互看或转移商品、订单归属。

停用会禁止该商家管理并将其商品及有效公开素材引用移出公开范围；新报价和下单拒绝，报价后停用也由下单 SQL 拦截。旧订单和售后保留供买家查看及管理员接手，重新启用后原采购者按最新权限继续处理。停用不是删库，也不是历史订单转让。

所有管理请求由服务器重新查询 D1 角色，不能凭前端按钮、请求正文中的角色或邮箱获得权限。写接口要求同源 `Origin`。Sites 的服务访问凭据只解决站点访问边界，不代表某个商家身份，也不授予这些管理权限。

**自行托管的身份边界：** 本 API 信任上述身份头的前提，是入口由可信 dispatch 过滤并注入这些头。不得把接受任意客户端同名请求头的裸服务公开部署；自行托管者需替换身份适配器或部署能验证身份、删除伪造头且封闭源站的网关。开发测试中伪造请求头仅用于模拟这个受信边界。

## 数据、迁移与素材

运行时绑定名为 `DB`（D1）和 `BUCKET`（R2）。托管配置与身份保存在忽略的 `.openai/` 中，公开仓库不包含某个现成站点的内部身份、凭据或运行数据。使用者需为自己的环境配置独立资源。

`db/schema.ts` 定义 `users`、`admin_bootstrap`、`products`、`media`、`orders`、`merchant_accounts`、`merchant_audit`、`product_inventory` 和 `inventory_events`。V0.7追加 `0002_demonic_mongu.sql`，V0.8追加 `0003_bright_shiva.sql`，不改既有迁移。SQL 迁移由 schema 生成并纳入源码；请求处理不会临时建表。已应用迁移不可改写，后续变更追加迁移。本地模拟库与托管 D1 是两个环境，不能认为本机初始化会自动出现在云端。

商家创建、修改、首次绑定与前后快照审计以同一事务保存，审计失败整体回滚。后台可读最新50条审计，包含动作、时间、操作者名称及前后资料；不开放删除审计或商家档案接口。商家审计覆盖档案变更，库存记录另覆盖人工调整、订单扣减及取消回补／待核对；两者不等同商品、订单全业务审计。

管理员可显式初始化六款模拟商品；初始化只插入缺失的编号，保留已有商品。商品最多 200 款，当前每款两种规格、整数分价格。保存携带 `expectedVersion`，版本不符返回 409；前端保留表单，须明确放弃修改并重新读取后再编辑。

上传支持 JPG、PNG、WebP、GIF（最大 5 MiB）及 MP4、WebM（最大 30 MiB），需要素材来源与授权说明。浏览器先检查可读取性，服务器再检查实际接收大小、声明格式与文件签名；这不是完整媒体解码、转码、恶意文件扫描或版权审核。编码兼容性仍需目标浏览器实际播放验证。

R2 写入成功且 D1 元数据保存成功后才确认上传成功。若 D1 失败会尝试清除对象，不报告保存成功。选择文件会先上传，但只有保存商品并上架后才向买家发布绑定；离开未保存表单或替换文件可能留下私人、未引用素材。当前没有素材库清理界面或定时回收任务，应按 D1 引用关系核对后再人工清理，不能按文件创建时间直接删除。

素材读取统一经 `/api/v1/media/:id` 校验：未发布、未被未停用卖家在售商品引用的素材，仅有products权限的归属商家或管理员可读。商品下架、商家停用或撤换后，原素材若无其他有效公开引用即恢复受限；此前已下载的副本无法撤回。接口支持 HEAD、单段 Range 与 416 响应，用于浏览器视频拖动，不直接公开整个 R2 桶。

素材来源文字由上传者填写，不构成已获授权的证明。内置图片仍按 [第三方素材说明](../THIRD_PARTY_NOTICES.md) 单独许可；历史 Pexels 视频与封面不随仓库提供。

## API 与故障处理

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/session` | 当前身份、角色、登录与退出入口 |
| `GET/POST /api/v1/admin/merchants` | 管理员列出或创建商家档案 |
| `GET/PUT /api/v1/admin/merchants/:id` | 管理员读取或按expectedVersion修改资料、权限和状态 |
| `GET /api/v1/admin/merchants/:id/audit` | 管理员读取最新50条商家变更审计 |
| `GET /api/v1/products` | 已发布目录 |
| `GET /api/v1/admin/products` | 当前商家可管理的目录，管理员可读全部 |
| `PUT /api/v1/admin/products/:id` | 按归属和预期版本新建或更新商品 |
| `GET /api/v1/inventory` | 已发布且卖家未停用商品的可售余量与当前采收批次，未配视为0 |
| `GET /api/v1/admin/inventory` | products权限读取可管理商品库存，商家仅自己商品 |
| `PUT /api/v1/admin/inventory/:productId` | 按库存expectedVersion设置两规格余量、批次、日期、介绍与调整原因 |
| `GET /api/v1/admin/inventory/:productId/history` | 同商品管理权限读取最新50条库存记录 |
| `POST /api/v1/admin/seed` | 管理员初始化模拟商品，JSON 正文为 `{}` |
| `POST /api/v1/media?kind=image\|video` | 上传二进制文件，携带文件名与来源请求头 |
| `GET\|HEAD /api/v1/media/:id` | 按发布状态或身份读取素材 |

订单接口与字段见 [API说明](API.md)。`GET /orders`按买家身份、`GET /admin/orders`按管理范围返回记录。创建必须携带服务端商品和库存报价版本与幂等键；发货、备注、售后和取消必须带expectedVersion。客户端金额只用于确认一致性，保存金额由服务端计算。不能提交任意订单JSON、买家或卖家身份。

遇到保存、上传或同步失败时，先保留表单并核对页面错误；不要把本机记录或上一次目录当成已写入云端。401/403 需重新确认登录与角色，409 需处理编辑冲突，413/415 需更换文件，503 需检查绑定、迁移和运行资源。错误响应不会返回底层数据库异常或凭据。

## 发布与验收

发布前执行 `npm run check`，并按当前部署配置完成 schema 迁移与 Worker 构建。以下必须在实际受信入口补验，单元测试不能代替：

- 匿名和无管理权限账户不能直接读写管理接口，商家不能改其他商家的商品或引用其私有素材。
- 第一次初始化绑定正确；其他稳定 ID 即使邮箱相同也不能再次初始化管理员。
- 上传、保存、刷新、跨设备查看和视频拖动通过；未保存素材不能公开读取，下架后原素材失去公开可见性。
- 并发版本冲突、断网、存储失败和权限撤销均显示失败，保留编辑内容，且不切换到本机后台。
- 云端订单按账户同步；本机旧订单不上传。两种模式均为模拟，不扣款、不实际发货。

当前源码实现和自动化检查结果需与发布记录一起核对。V0.5托管和真实文件历史验收见 [2026-11-01 验收记录](QA-2026-11-01.md)；不能据历史通过推定V0.7商家管理、V0.8库存或所有账户、设备和故障情形均已实际覆盖。

V0.5历史独立源码检查执行九组仓库云 API 测试，基于实际 SQL 迁移覆盖权限、初始化、版本、上传和媒体可见性。额外临时检查验证了商家角色撤销即时生效、多个在售引用撤下后的素材权限、私有 HEAD 在访问 R2 前拒绝，以及长度谎报与底层异常不泄漏。额外脚本为本地 QA，不替代真实 D1／R2 和平台入口验收。

备份恢复、管理员恢复、商品订单全业务审计、上传配额、素材回收、完整媒体转码和旧本机订单迁移仍是后续工作。维护者应在接入真实数据前完成 D1 数据及 R2 对象的配套备份、恢复演练和角色恢复流程；本仓库目前没有自动备份任务。

R2 Range 与对象读取实现参考 [Cloudflare R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。Sites 身份与资源绑定以安装版本的 Identity and Secrets、Storage 说明为准。

## V0.7 商家管理的本机验收

先构建、应用实际迁移，并使用 `npm run preview:cloud` 启动本机Worker；另一个终端运行：

```sh
node scripts/smoke-merchants-local.mjs http://127.0.0.1:8787
```

脚本仅接受HTTP回环根地址，使用本机模拟身份，创建模拟商家、商品和订单，检查绑定、三权限、跨商家隔离、停用、旧单保留及审计，结束时尝试停用模拟商家，保留历史供检查；不删除数据库或历史。默认管理员为本机 `local_seedy/seedy@sites.test`，独立本机配置可通过 `SMOKE_ADMIN_ID`、`SMOKE_ADMIN_EMAIL` 指定其模拟管理员。不要把伪造身份头当作托管登录验证，也不要添加生产身份切换入口。

V0.7生产验收还需真实授权的不同采购者账号及站点访问权。应用商家档案不会改变Sites私有站点访问策略，真实采购者须另具备站点访问权限。当前自动化与本机HTTP检查不代表生产商家CRUD或手机与电脑的真实人工交互已验收；发布结果以对应QA记录为准。本轮按用户要求使用命令行，不操作用户浏览器或Computer Use。


## V0.8 库存与当前批次的使用

1. 在云后台“商品管理”先保存商品，再点击该商品的“库存”或进入“库存批次”。只有products权限可见和管理，商家只能处理自己的商品，管理员可处理全部。
2. 填写两种规格当前尚可出售的整数份数。新建、历史和初始化示例商品都默认未配置，按0处理，不能新下单。若只体验模拟流程，可点击“填入模拟库存20／12”，核对批次编号、日期和介绍，再显式保存。按钮不自动写入，迁移不会自动补正库存。
3. 填写批次编号、可留空的有效采收日期、模拟介绍和本次调整原因。这里记录当前可售余量，不是批次总产量、入库总量或重量；不要把已经由订单扣减的数量再重复计入。每次人工设置每规格0–999999份。
4. 改批次编号或采收日期会生成新批次标识；只改余量或说明保留当前批次。当前每商品只有一个批次，不等同完整多批次仓库。新订单保存当时的批次编号、日期和介绍，后续更新不改旧单。
5. 模拟下单按服务端报价与库存版本确认后，在同一事务建单及扣减。看到版本冲突时保留需要的草稿，先核对云端订单和余量，再明确放弃旧填写并重新读取，不能把旧余量直接覆盖回去。
6. 符合取消条件的未发货单，只有全单仍为原批次且数值可安全回补时才一次性整单回补；任一商品换批次或需核对，取消仍成功但整单标记待核对，不自动增加任意商品库存。库存记录和订单详情会显示提示。采购者核实原批次实物余量后可人工调整并说明原因。
7. 售后申请、撤回、退款或补发处理不自动回库；没有库存批次快照的历史订单取消也不回补。取消回补可能使余量超过999999，页面可正常显示，重新人工设置仍适用上述输入上限；数据库另有限制安全非负整数。

人工调整、下单扣减、同批次取消回补及待核对记录位于`inventory_events`，包含前后快照、原因、操作者、订单编号和时间，后台读取最新50条。写入和对应记录在同一D1事务，失败整体回滚；失败或响应丢失时先重新读取，不反复创建新单。纯静态本机页只说明需要云端，不声称保存或扣减了云库存。

本轮仍使用模拟资料，无支付或真实收发货。库存接口、事务和页面事件的自动化检查不替代可信登录入口、手机上传播放、视觉布局或真实多设备人工验收。发布与实际检查结果由本轮QA记录补充，不沿用历史验收推定通过。

## V0.9 买家目录排查

买家从首页、逛产区、采购者店铺进入商品。只读 `/api/v1/storefront` 从已上架商品推导产区和店铺，不需要迁移或单独初始化；店铺资料使用模拟介绍，已绑定商家显示其业务名称，不公开登录邮箱。定边筹备只是空白结构，没有实际采购合作。

目录刷新失败时会提示重试，商品仍可查看，但不能把关系未知的商品提交为新订单。先检查商品是否上架、商家是否停用、目录接口是否可读；不要以补本地假店铺或自动设置正库存绕过错误。此前不确定的订单可在“我的订单”确认原请求。采收视频沿用商品媒体绑定，替换后须保存上架；本轮未增加独立店铺视频管理。

本机可在完成构建、迁移并启动回环Worker后运行 `node scripts/smoke-storefront-local.mjs http://127.0.0.1:8787`。脚本仅接受回环地址，使用明显模拟的临时商家和商品，结束下架商品、停用档案。不得把本机身份模拟用于生产验收。
