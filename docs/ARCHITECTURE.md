# 架构说明

## V0.8：云端库存、当前批次与模拟履约

买家与后台继续使用 `public/` 中的原生 HTML、CSS 和 JavaScript ES Modules。`npm start` 运行独立静态演示；云部署使用 Vinext／Cloudflare Worker 处理业务 API，将商品、库存批次、库存记录、订单、售后及素材元数据保存到 D1，文件保存到 R2；`dist/` 是构建输出。服务端订单仍为无支付的模拟业务。

| 文件或目录 | 职责 |
| --- | --- |
| `public/index.html`、`app.js`、`experience.js`、`styles.css` | 买家页面、购物车、收藏与模拟订单 |
| `public/admin.html`、`admin.js`、`admin.css` | 后台登录门禁、商品编辑与云端／本机订单管理 |
| `public/cloud-client.js` | 模式探测、登录状态、API 请求与连接错误 |
| `public/catalog-store.js` | 本机／云目录适配、商品版本与保存 |
| `public/order-store.js` | 云订单读取、分页、报价、幂等提交及状态变更；不存本地订单，防账号切换期间旧响应回流 |
| `public/media-store.js` | IndexedDB 或云上传适配、媒体地址、浏览器可读性检查 |
| `public/merchant-store.js` | 仅管理员调用的商家档案、权限与审计读取，静态模式不伪装为真实授权 |
| `public/inventory-store.js` | 公开库存与有products权限的后台库存／历史接口；不混入商品编辑字段，不持久化到本机 |
| `public/model.js` | 商品校验、整数分金额、报价、订单快照、模拟发货与售后状态 |
| `app/` | Vinext 入口与云 API 路由；平台登录辅助保留 Sites 集成 |
| `server/cloud-api.js` | 受信身份、D1 角色、商品归属、字段及版本检查、素材上传读取 |
| `server/order-api.js` | 服务端报价、订单归属与快照、幂等键、原子版本更新、发货和售后历史 |
| `server/merchant-api.js`、`server/merchant-access.js` | 管理员商家 CRUD、事务审计、三权限策略及最终 SQL 权限条件 |
| `server/inventory-api.js` | 按商品归属管理可售份数、当前批次、库存版本和事务记录；供订单原子扣减／回补使用 |
| `db/schema.ts`、`drizzle/` | 云端表定义和版本化 SQL 迁移 |
| `scripts/server.mjs` | 本机静态服务与显式演示标记，不提供云业务 API |
| `public/assets/` | 示意素材与来源记录，独立于源码 MIT 许可 |
| `tests/` | 模型、存储、静态 HTTP 与迁移后的云 API 测试 |

本地入口为 `/` 与 `/admin.html`，另兼容 `/admin`；买家路由使用 URL hash。

## 模式与数据归属

前端首先请求 `/api/v1/session`。仅 `404` 且正文带 `mode: local-demo` 时启用本机模式。云接口异常、未标记的 404、断网或鉴权失败均保持云端错误状态，避免将本机修改误报为服务器保存成功。

| 内容 | 本机演示 | 云端原型 |
| --- | --- | --- |
| 身份和角色 | 无登录或服务器授权 | Sites dispatch 身份与 D1 `users` |
| 商家档案、地区与权限 | 不提供真实账号管理 | D1 `merchant_accounts` 与 `merchant_audit`，不自动填充 |
| 商品与状态 | localStorage | D1 `products` |
| 库存、当前采收批次与记录 | 只说明需要云端，不模拟云库存保存 | D1 `product_inventory` 与 `inventory_events`，默认未配置视为0 |
| 上传文件与元数据 | IndexedDB | R2 文件、D1 `media` |
| 订单、发货与售后 | localStorage | D1 `orders`，同一登录身份跨设备读取 |
| 购物车、收藏、足迹 | localStorage | 仍为 localStorage，不跨设备共享 |
| 当前规格、数量、示例地区 | sessionStorage | 仍为当前标签页记录 |
| 客服对话、编辑表单 | 页面内存 | 仍为本机演示 |

沿用 `longshang-demo-*` 键兼容本机记录，不自动上传这些数据。不同来源各自保存本地数据，复制代码或登录其他设备不会迁移旧本机记录。云端订单在列表、详情和后台按账户读取，同步时间以成功完成读取为准。云端初始为空目录，由管理员显式加入模拟商品。

## 身份、权限与 API

服务器只在可信 Sites dispatch 入口后使用平台注入的稳定用户 ID 和邮箱；登录和退出由平台负责。`BOOTSTRAP_ADMIN_EMAIL` 用于一次性匹配初始化，D1 单例绑定稳定 ID；后续授权由 D1 角色决定。客户端角色或归属字段不能改变权限。

管理员按登录邮箱创建至多200份商家档案，分配地区与 `products/orders/aftersales` 权限。首次可信邮箱匹配未绑定档案时，以事务绑定唯一稳定 ID、授予 `merchant` 并记录审计；以后按稳定 ID 查档案。停用档案也完成绑定但不放行管理，已绑定档案不可改邮箱。单凭 `merchant` 角色、客户端角色切换或重复邮箱不获得权限；明确撤销的角色不因再次登录恢复。没有密码、邮件邀请或管理员升级接口，已知管理员不可被纳入商家档案。地区是展示资料，不构成按地区共享权限或转移归属。

| 接口 | 授权与校验 |
| --- | --- |
| `GET /api/v1/session` | 当前身份与登录入口，匿名无管理权 |
| `GET/POST /api/v1/admin/merchants` | 仅admin，读取全部至多200份或新建档案，不自动生成或发送邀请 |
| `GET/PUT /api/v1/admin/merchants/:id`、`GET /api/v1/admin/merchants/:id/audit` | 仅admin，版本控制的档案修改及最新50条前后快照审计 |
| `GET /api/v1/products` | 只返回已发布且卖家未停用的商品 |
| `GET /api/v1/admin/products` | merchant需products权限且仅自己的商品，admin全部 |
| `PUT /api/v1/admin/products/:id` | 同源、products权限、商品归属、字段白名单、素材归属和类型、`expectedVersion` |
| `GET /api/v1/inventory` | 已发布且卖家未停用商品的库存与采收资料，缺少库存记录返回未配置及0余量 |
| `GET /api/v1/admin/inventory` | products权限；商家仅自己商品，admin全部，包含未配库存商品 |
| `PUT /api/v1/admin/inventory/:productId` | products权限、商品归属、同源、expectedVersion、两规格份数和批次字段校验 |
| `GET /api/v1/admin/inventory/:productId/history` | 同一商品管理权限，最近50条人工调整、扣减、回补和待核对记录 |
| `POST /api/v1/admin/seed` | 仅管理员，插入缺失的模拟商品，不覆盖已有资料 |
| `POST /api/v1/media?kind=image\|video` | products权限、大小、MIME／格式签名、文件名和来源说明 |
| `GET\|HEAD /api/v1/media/:id` | 未停用卖家已发布商品引用的素材可读；其他仅有products权限的所有者或admin，支持单段Range |

商家不能绑定别人的私有素材，管理员有全局管理权限。写请求检查 `Origin`，不开放跨站 CORS。自行托管需提供可信身份适配器；直接公开信任任意请求头的裸源站不具备这一身份保证。

更新商品增加版本。SQL 再次比较 `expectedVersion`，冲突返回 409，避免检查后并发覆盖。前端保留冲突表单，重新载入须明确放弃修改。保存失败不报告成功，也不回退写入本机。

会话返回 `permissions` 与自己的 `merchant` DTO，管理员拥有三权限，采购者必须同时满足角色、启用状态与授权项。前端按身份和权限范围隔离私有缓存，变化时丢弃旧范围的在途响应；服务端商品与订单写 SQL 再次读取当前角色、档案和动作权限。商家档案变更与前后快照审计在同一 D1 batch 提交，首次绑定也在事务内完成，审计失败则整体回滚。不会修改历史商品 owner_id 或订单 seller_id。

素材先上传为私人记录，再保存商品绑定；仅在售引用开放读取。R2 和 D1 不是同一事务：对象保存后元数据失败，会尝试删除对象并报错；异常可能留下未引用对象，没有元数据的对象不能经媒体 API 公开读取。当前没有自动回收或完整素材历史管理。

## 可售库存与当前批次

`product_inventory` 每商品一行，独立于商品 JSON 和商品版本。两种规格 `small/family` 记录当前还能出售的整数份数，不是批次总产量、重量或已扣减前的总数；管理员和有products权限的原商家可人工设置。未配置库存等同0，迁移和商品初始化不自动填入正库存。后台“填入模拟库存20/12”只填表，必须显式保存；首次保存用库存版本0，已有记录按最新版本更新并填写调整原因。

每款商品仅有一个当前采收批次，包含批次编号、可空的采收日期和介绍。首次设置或更改批次编号／采收日期时生成新的稳定 `batchId`；只改余量和说明保留原批次。新订单逐项保存批次介绍快照，之后编辑不改旧单。这是单当前批次的演示库存，不提供完整多批次仓库、先进先出、实际入库出库或损耗盘点。

人工每规格设置0–999999份，取消回补允许余量超过这个输入上限，避免单纯因为回补超过上限阻止取消。数据库仍限制为安全非负整数。库存每次调整、扣减及回补增加版本，`inventory_events`保存前后快照、动作、原因、操作者、关联订单和时间；管理接口只读最新50条，不公开给买家。

人工修改与记录在同一D1事务，订单创建与库存扣减也在同一事务。建单前核对全部商品与规格的可售数量、商品版本、库存版本、批次与卖家状态；仅本次新生成的订单成功插入才扣减，唯一幂等键碰撞不会重复扣减。任一环节保存失败整体回滚，不能留下只有扣减没有订单的结果。

符合状态条件的未发货订单取消时，用唯一回补标记保护整单事务。只有所有商品仍是下单批次且满足安全数值范围才整单回补一次；任一商品换批次或需核对时，取消仍成功，整单标记 `stockRelease.status=review`且不回补任何商品，记录待人工核对。旧版本无库存批次快照的订单取消不回补；售后申请、撤回、退款或补发处理也不自动回库。管理员／采购者核实后另行人工调整，并填写原因。

## 云端订单与兼容的本机演示

- 每款保留 `small`、`family` 两种规格，使用整数分价格。
- `draft`、`published`、`offline` 控制可新增购买的商品，云公开目录只含已发布项。
- 同商品与规格在购物车合并，同一商家的一笔模拟合单只收一次运费；跨商家暂拒绝合单。
- 订单保存名称、规格、数量和金额快照，后续改价不重算旧单。
- 主状态为 `created`／`cancelled`，模拟发货放在 `fulfillment`，整单售后为 `submitted`／`resolved`／`withdrawn`。
- 模型阻止重复、取消单、待处理售后及整单退款完成后的发货；云 API 同样独立执行状态和权限检查，不依赖页面隐藏按钮。

本机数据可被用户自行修改，与云数据分离。云端 `orders` 持有 buyer_id、seller_id、request_key、请求指纹、订单 JSON 快照、版本与时间；买家只读自己的订单，商家只读其 seller_id 订单，管理员可处理全部。买家响应移除内部备注。

管理订单读取需要 `orders` 或 `aftersales`；只有售后权限时，列表和详情仅返回已有 `afterSale` 的自己订单，不暴露无售后订单。发货和备注需要 `orders`，处理售后需要 `aftersales`。采购者停用后不能管理，公开商品及其有效公开媒体引用隐藏，新报价和下单拒绝；旧单保留，管理员可接手，重新启用后同一采购者按新权限继续处理。

下单先按 D1 当前已发布且卖家未停用的商品重新报价。创建在同一D1 batch中用 INSERT SELECT 再次核对商品版本、归属、上架、卖家未停用及全规格库存版本／数量，再原子扣减；`buyer_id + request_key` 唯一，完全相同请求重放返回同一订单，参数不同返回409。即使商家后来停用，旧单重放仍返回原单。订单更新在SQL的WHERE条件中再次核对版本、归属和当前动作权限，失败不覆盖。

售后当前状态和逐次快照历史同时持久化；申请、撤回和处理均递增订单版本。整单模拟退款完成后不能再发货、取消或重复申请。图片保留订单时快照；如当时的云素材已受限，显示快照内置图，不泄漏下架私人素材。历史订单名称和金额不依赖当前公开目录。

前端单次待确认下单请求在 sessionStorage 中按账号保存幂等键和原始报价；仅用于恢复本标签页的响应丢失重试，不承担订单持久化。列表按服务端游标读取所有页（客户端防循环与100页上限），页面不静默截去前100笔之外的订单。

## 后续接口演进

仍未实现真实支付、完整仓储、实际快递、部分售后、自动拆单和跨商家运费；V0.8库存扣减只是无支付模拟流程。历史本机订单默认留在演示环境，不当作真实交易导入。

V0.7已实现商家档案权限与变更审计，V0.8追加库存／当前批次与库存记录；多商家运营仍需管理员恢复流程、素材审核、视频封面／视频专属拍摄日期／版权字段、历史版本、上传配额和回收、商品订单等全业务审计、备份恢复。通用来源说明不能替代这些流程。交付见 [路线图](ROADMAP.md)，部署与故障处理见 [云端运行说明](CLOUD-OPERATIONS.md)。

云端买家当前标签页会把曾读到、随后退出公开目录的商品保留为不可购买的下架记录，供购物车移除。重新打开页面后，无法读取的旧购物车商品可能被清理；持久化购物车快照仍是后续任务，与已经云同步的订单快照不同。
