# 开发路线与验收

本项目先把少量景泰特产的展示、订单与服务做好，再根据真实使用反馈扩展品类和地区。每一阶段完成验收后再进入下一阶段，不以页面数量代替业务验证。

## 已有基线：V0.4 本浏览器演示

买家商城与后台共享同源浏览器数据，支持动态商品、两种规格、素材替换、上下架、购物车、合并模拟订单、发货记录和整单售后。没有服务端账户、云存储、真实支付与物流接口。

保留以下回归标准：

- 新商品保存为草稿时不进入买家在售列表；上架后可查详情并生成模拟订单。
- 两种规格使用各自价格；下架商品保留在购物车但不能结算。
- 多商品订单只计算一次模拟运费；改价后旧订单金额不变。
- 后台发货与售后意见能在同源买家页恢复显示；重复提交和存储失败有明确处理。
- 本地素材保存、刷新恢复、视频播放需要真实浏览器验收。

## 下一里程碑：V0.5 账户角色与服务端闭环

目标是让受邀测试人员通过不同设备读取同一目录，分别管理自己的资料与订单。维持小范围、单店运营，先保留模拟交易标识；支付、企业注册与开放招商不作为本阶段前置步骤。

| 工作包 | 交付内容 | 验收条件 |
| --- | --- | --- |
| 账户与权限 | 登录、退出及顾客／运营／管理员最小权限；明确素材归属和可管理商品范围 | 未登录不能调用管理接口；顾客只能读取自己的订单；运营不能修改未授权商品或他人素材；直接请求接口同样被拦截 |
| 商品目录接口 | 服务端保存商品、规格、草稿／上架／下架状态与版本 | 两台设备能读取同一已发布商品；保存失败不显示成功；并发编辑冲突有提示；下架后服务端拒绝新订单 |
| 素材接口 | 受控上传、素材编号、归属、商品绑定、读取与替换 | 校验类型及大小；失败不替换原素材；无权限者无法修改；详情和产地读取同一已发布素材；有来源与授权记录 |
| 订单接口 | 服务端报价、创建、查询、备注、模拟发货与售后处理 | 不信任客户端总价；重复创建请求只产生一单；保留金额快照；重复发货、取消单发货与待处理售后发货被阻止 |
| 数据与运维 | 配置示例、迁移说明、备份恢复步骤与关键操作日志 | 不提交凭据；能在测试环境部署；完成一次备份恢复；日志能定位操作者与操作结果 |
| 自动化与浏览器验收 | 权限、接口、模型回归及完整交互检查 | 正常与拒绝路径均有测试；真实媒体上传与跨设备读写通过；已知限制写入文档 |

实施顺序：先确定数据结构和接口约定，再完成认证与权限，随后接入商品和素材，最后迁移订单与售后。现有模型尽量复用，浏览器存储通过适配层逐步替换。原演示数据不自动当作真实客户数据导入服务器。

进入下一阶段的最低条件：

- [ ] 账户隔离、素材归属和管理权限由服务端执行，并有越权测试。
- [ ] 一条“运营保存并发布商品 → 顾客读取 → 生成模拟订单 → 后台处理 → 顾客查看结果”的跨设备流程通过。
- [ ] 价格篡改、重复提交、下架、并发编辑和存储失败均有测试。
- [ ] 商品、素材和订单有备份恢复方案，测试环境故障能恢复。
- [ ] 浏览器实际上传、刷新与播放通过；演示数据和试运营数据明确区分。

## 验收之后：小范围试运营

先选少量已核实的商品与受邀测试者，验证供货、分级、包装、试寄、到货反馈和售后记录。用真实记录判断是否扩大，而非先把全国品类开发齐全。

开始接受真实订单前，需逐项确认商品资料、供货责任、包装与配送报价、售后规则、收件资料处理方式，以及适用的经营与收款条件。真实付款、发货和退款是另外的业务接入，不能沿用演示状态假装已完成。

试运营重点记录：订单能否准确履约、实际成本与运费、破损及售后原因、复购反馈和每笔订单的收支。指标先按小样本记录，再据此设定扩张门槛。

## 后续按需求推进

- 按真实货源增加甘肃品类，再扩展到其他产区；补充产地、批次与采购责任记录。
- 在履约需要时增加按产地拆单、差异运费、部分售后与采购结算。
- 在服务端闭环稳定后选择微信小程序等前端入口，复用接口；独立 App 后续再评估。
- 根据试运营结果决定支付、真实物流、消息通知和人工客服接入顺序。

以上是开发方向，不代表这些功能已实现或已与任何供应方、支付机构和物流公司合作。
