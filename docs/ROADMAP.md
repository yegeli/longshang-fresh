# 开发路线与验收

先完成少量景泰特产的展示、目录与服务，再根据真实反馈扩展。页面存在、自动化通过和实际云端验收是不同状态；计划不作为已交付承诺。

## V0.4：本浏览器演示基线

五个买家导航和本机后台支持动态商品、两种规格、素材替换、上下架、购物车、合并模拟订单、发货记录与整单售后。`npm start` 保留独立演示，没有服务器授权或跨设备共享。

回归标准：草稿不进入在售列表；下架不能新购买；规格价格正确；合单一次运费；改价不影响旧单；重复、取消及待处理售后订单不能发货；失败明确报错。浏览器还需验证文件选择、刷新恢复和播放。

## V0.5 已完成基线：云端商家、商品与素材

该阶段范围为受信 Sites 登录、D1 角色和目录、R2 素材。订单与售后继续本机模拟，不接真实支付或物流。实现落盘不表示对应线上环境已验收。

| 交付 | 关键验收 |
| --- | --- |
| 平台身份与权限 | 匿名／buyer 直调管理接口被拒，merchant 只能编辑自己的商品与素材；管理员一次绑定稳定 ID，重复初始化不提权 |
| 云目录 | 不自动导入本地资料；显式初始化模拟商品；跨设备同一在售目录；并发冲突 409 并保留表单 |
| 云素材 | 校验大小、签名及来源字段；私人素材不能越权读或绑定；商品保存上架才公开引用；下架后受限；HEAD／Range 不绕过权限 |
| 失败路径 | 鉴权、版本、存储及断网错误明确反馈；不切回本机；R2／D1 失败不宣称成功 |
| 本机兼容 | 静态演示标记明确，订单不自动上传；改价保留旧金额；云页面说明订单不跨设备 |

自动化之后仍需在真实入口核验管理员、普通账户与不同商家的拒绝路径，以及实际上传、保存、刷新、跨设备展示和视频拖动。发布记录应注明已通过与未完成项目，签名测试不能替代真实播放。

## V0.6 已完成基线：云端模拟订单与售后

| 工作包 | 验收条件 |
| --- | --- |
| 服务端报价和建单 | 不信任客户端总价；读取当前商品与运费；稳定请求标识防多单；事务保存金额快照 |
| 订单归属和处理 | 顾客只读自己的订单，商家只处理授权范围；重复、取消／退款／待处理售后发货被阻止；并发状态不覆盖 |
| 云售后 | 申请、撤回、意见跨设备可读；归属、幂等和失败路径有测试，仍不伪称实际退款 |

以上订单功能已实现，测试和部署结果见 [V0.6验收记录](QA-ORDERS-2026-11-01.md)。没有支付、真实库存或真实快递；同单限同一商家，旧本机订单不导入。真实手机与电脑的完整人工交互仍待补验。

## V0.7 已完成基线：商家账号与采购者权限

| 工作包 | 验收条件 |
| --- | --- |
| 管理员商家后台 | 创建、修改、停用及重新启用至多200份商家档案；名字、登录邮箱、地区、三权限和状态有校验与版本控制 |
| 可信身份绑定 | 首次可信邮箱匹配原子绑定唯一稳定ID；同邮箱不同ID不能继承，绑定后档案邮箱不可改，不自建密码或模拟生产身份 |
| 权限与归属 | products仅自己商品素材；orders仅自己订单并可发货／备注；aftersales仅自己已有售后的订单及处理；仅角色无档案不放行 |
| 停用与旧单 | 停用失去管理权、公开商品隐藏、新报价及建单拒绝；旧单保留管理员接管；不转移原归属 |
| 管理员与变更记录 | 不能通过商家后台升级或纳管管理员；创建、修改、绑定与前后快照审计事务落盘，失败回滚，最新50条可查 |

上述功能已实现，使用模拟资料，不自动填充商家、不发邮件、不接支付。真实SQLite迁移测试和本机Worker脚本验证接口；`scripts/smoke-merchants-local.mjs`仅接受回环地址。生产商家CRUD、真实采购者多账户登录及手机电脑人工交互需另行验收，不能用本机模拟身份替代。商家档案也不授予Sites私有站点访问权。

## V0.8 当前里程碑：可售库存与采收批次

| 工作包 | 验收条件 |
| --- | --- |
| 库存后台 | products权限仅管理自己商品，admin全部；每规格整数可售份数、缺货／低库存／未配置筛选、版本冲突保留填写、调整原因与最近50条记录 |
| 默认与模拟边界 | 新旧商品都不虚构正库存，未配视为0且不可新下单；后台20／12模拟按钮只填表，显式保存才生效；本机静态页不模拟云库存 |
| 当前采收批次 | 批次编号、可空日期和介绍；改编号／日期产生新batchId；新订单保留批次快照，旧订单不受后续编辑影响 |
| 原子扣减 | 新报价含库存版本，创建在同一事务核对全规格数量、版本与卖家状态并扣减；同幂等请求不重复扣减，失败回滚，抢购不卖超 |
| 取消与核对 | 符合条件未发货单仅在全单仍同批次时一次回补；任一换批次则取消成功但整单review、不回补；无库存快照旧单及售后不自动回库 |

这里的库存是当前可售余量，单位为每种规格的“份”，不是农场总产量。每商品只有一个当前批次，尚无完整多批次仓储、先进先出、采购结算或真实物流。资料继续模拟，不接支付。源码、自动化与本机Worker检查须分别记录，不能声称已完成生产登录后操作或真实手机验收。

## 后续：运维与试运营准备

| 工作包 | 验收条件 |
| --- | --- |
| 权限与运维 | 管理员恢复流程、商品订单等全业务审计、D1／R2 配套备份和恢复演练；扩展现有商家权限审计 |
| 素材生命周期 | 上传配额、遗留清理、未引用回收、稳定入口、历史版本；多上传者归属及审核发布／撤回 |

视频继续绑定具体商品和产地。已有标题与通用来源说明；视频独立封面、视频拍摄日期、版权专用字段、审核预览、发布／撤回及历史版本仍需补齐。替换素材保持买家入口，上传者只管理自己的素材，管理员变更需记录。

支付、企业注册、开放招商与独立 App 不是本轮原型开发前置步骤。真实交易另行接入，不能把本机模拟履约当作实际凭证。

## 进入小范围试运营之前

- [ ] 在实际入口验证管理员、采购者三权限、停用及越权拒绝；商家绑定竞争与权限收缩已由本机测试覆盖。
- [ ] “商家发布 → 买家读取 → 云模拟订单 → 后台处理 → 买家查看”跨设备闭环通过；接口已覆盖全链路，真实设备交互仍需补验。
- [ ] 价格篡改、重复请求、下架、并发抢最后一份库存、重复取消、换批次核对、审计或扣减存储失败均有测试。
- [ ] 商品、素材和订单可配套备份恢复；目标设备上传、刷新与播放通过。
- [ ] 演示／试运营数据边界明确；核对货源、包装配送、售后、资料处理与适用经营收款条件。

试运营先核实少量货源并试寄，记录履约准确性、实际成本运费、破损售后与复购，再决定扩张。后续按需求增加产区、拆单运费、采购结算和部分售后；服务端稳定后评估微信小程序入口，复用接口。

以上方向不代表已建立真实供货、支付或物流合作。维护说明见 [CLOUD-OPERATIONS.md](CLOUD-OPERATIONS.md)。
