# 手机完整模拟流程与一次性库存配置

本功能按项目所有者明确要求配置模拟库存，不接支付、真实物流或退款。六款内置模拟商品为苹果、枸杞、梨、土豆、玉米、洋葱；每款初始化 `small=20`、`family=12`，合计192份。两种规格的实际名称以商品详情为准，数量按份计算。

## 手机怎么体验

打开已部署的商城，使用现有管理员同一账号登录。该账号可同时作为买家下单和进入后台处理，不需要额外创建商家。手机与电脑登录同一账号可以查看同一批云端记录；站点访问名单和业务权限仍分别校验。

1. 商城选择商品和规格，加入购物车，点“去结算”，选择示例收货地区，点“生成模拟订单”，记下订单编号。
2. 打开同站点的 `/admin.html`，点“订单管理”并刷新，找到同一订单、打开详情。核对预填的演示物流与 `DEMO-` 单号，点“确认模拟发货”。
3. 回商城“我的订单”，刷新，在“待收货”确认模拟收货，订单变为“已完成”。
4. 从该订单点“申请售后”，选择模拟退款或补发，填写模拟描述并提交。
5. 回后台“售后管理”，刷新、查找同一订单，填写处理意见，确认模拟退款或补发完成。
6. 回商城刷新，点“查看售后”，核对最新结果。商城“客服与帮助”中的“完整体验指南”有逐步入口。

下单按规格扣库存。取消订单只在原批次仍匹配时回补，否则交采购者核对；发货、收货、售后均不自动补库存。库存用完后由有商品权限的管理员在“库存批次”核对并补充，不会刷新自动加满。没有上传的视频仍显示待补充。

## 配置入口与授权

`POST /api/v1/maintenance/demo-inventory` 是默认关闭的维护入口，不是普通用户或商家的接口。仅接受空 JSON 对象、同源 `Origin` 和请求头 `X-Demo-Setup-Token`。必须先由站点所有者明确授权这一次模拟库存配置，并通过 Sites 的运行环境工具设置：

- `DEMO_INVENTORY_SETUP_TOKEN`：随机32字节的64位十六进制密钥，作为 secret 保存。
- `DEMO_INVENTORY_SETUP_EXPIRES_AT`：标准 UTC ISO 字符串，例如由 `new Date(Date.now()+3600000).toISOString()` 生成，最多24小时有效。

配置环境后部署才生效。私有站点另需 Sites 服务访问凭据；它仅通过站点访问门禁，不携带或冒充访客身份。不得发送伪造的 `oai-authenticated-user-*` 请求头，不读取浏览器 Cookie。

命令行助手为 `node scripts/configure-demo-inventory.mjs`。启动后通过隐藏标准输入提供 JSON，字段为 `url`、`siteServiceToken`、`setupToken`、`mode`（明确选 `apply` 或 `verify`）。凭据只能在内存和隐藏输入中流转，不放命令参数、源码、日志或仓库文件中。仅接受站点 HTTPS 根地址或 HTTP loopback；拒绝重定向。`apply` 检查访客权限、库存初始化结果和商品资料未改动；`verify` 用已撤销的原密钥确认入口返回404。

配置成功后立即将两个运行环境值显式覆盖为 `disabled`，部署后运行 `verify`，必须用原密钥实际得到404才确认关闭。不要只凭环境列表已移除字段就推断运行中的密钥失效；若旧值仍生效，保存并部署新版本再核对。确认关闭后可以清理这两个无效占位变量，但不把清理后的列表当成运行验证。失败或中断也应关闭该临时入口；在重试前先核对持久操作记录与库存，而非重置数据。密钥到期还会由服务端拒绝请求。

## 数据保护

仅处理六个固定商品编号，且必须当前已发布、属于初始管理员、管理员仍有效、商家未停用、产地与介绍均保留“模拟”标记、规格恰为 `small` 与 `family`。已有库存记录或库存历史的商品一律跳过，即使余量为0也不会补满。商品归属、价格、图片、视频及历史订单均不修改，采摘日期留空。

`setup_operations` 记录固定操作 `demo-inventory-v1` 与随机请求标识；并发请求仅一个事务能认领。系统审计身份、库存、调整记录与完成摘要通过同一 D1 `batch` 事务写入，任何失败整体回滚。重复执行只返回原结果，不重置库存。无合格商品时返回409，不占用操作记录。数据库迁移只创建空表，不包含种子数据或库存回填。

审计显示“一次性模拟库存配置（系统）”，明确与管理员手工操作区分。该身份仅为低权限审计记录，`system:` 命名空间禁止访客登录，不获得商家权限。生产配置完成后可通过受控数据库查看器核对操作摘要和六条初始库存记录；这些运行数据不上传公开仓库。
